# Grok Media Saver — คู่มือใช้งาน + ความรู้จากการซ่อม

> สรุปจากการ debug จริงกับ Claude (5 ก.ค. 2026) — extension อยู่ที่ `D:\Downloads\grok-media-saver-v6.0` (เวอร์ชันปัจจุบัน **6.1.1**)

## มันคืออะไร

Chrome extension (โหลดแบบ unpacked ผ่าน `chrome://extensions` → Developer mode) สำหรับ**กวาดดาวน์โหลดรูป+วิดีโอทั้งหมด**จาก Grok Imagine (`grok.com/imagine/saved`) — รวมถึงรูปที่แก้ซ้ำหลายรอบ (sub-edits) และวิดีโอที่ซ่อนอยู่ในแต่ละโพสต์

**หลักการทำงาน 3 ชั้น:**
1. **ดักเน็ตเวิร์ก** (inject.js) — hook fetch/XHR ของหน้าเว็บ เก็บ URL สื่อทุกตัวที่ไหลผ่าน API
2. **Replay API** (content.js) — จับ request ของ gallery API แล้วยิงซ้ำไล่ทีละหน้าจนจบ `nextPageToken` → **นี่คือตัวหลักที่ทำให้ได้ครบ** ไม่ต้องพึ่งการเลื่อนหน้า
3. **เก็บจาก DOM ระหว่างเลื่อน** — ตาข่ายเสริม เพราะ grid ของ Grok เป็น virtualized list (รูปที่เลื่อนผ่านถูกถอดจาก DOM)

## วิธีใช้ที่ถูกต้อง

1. เปิด `grok.com/imagine/saved` → เปิด side panel ของ extension
2. เลือกโฟลเดอร์ปลายทาง (หรือปล่อยให้ลง `Downloads/GrokMedia_วันที่`)
3. กด **Auto-Scan All** แล้วรอจนจบ
4. **อ่านบรรทัด status ก่อนโหลด** — ต้องเห็น `ดึงจาก API ครบ N หน้า` ถึงจะมั่นใจว่าครบ
5. กด Download

**กฎสำคัญ:**
- ❗ **อยากได้ทุกรอบแก้ (variant) → อย่ากด "ตรวจซ้ำ" ก่อนโหลด** — รอบแก้หน้าตาใกล้กันมาก ระบบ dHash อาจมองเป็นไฟล์ซ้ำแล้วยกเลิกเลือกให้ ใช้ปุ่มนี้เฉพาะตอนอยากคัดเหลือรูปเด่นต่อชุด
- ปิด panel แล้วรายการหาย → ต้องสแกนใหม่ (ปกติ ไม่ใช่บั๊ก)
- extension จำประวัติ "เคยโหลด" ถาวร และ**ยกเลิกเลือกไฟล์เก่าให้อัตโนมัติ** — ถ้าอยากโหลดซ้ำให้กด "ล้างประวัติ"
- Deep Scan ไม่ต้องเปิด — API replay ครอบคลุมกว่าและเร็วกว่ามาก

**อ่านสัญญาณ status:**
| ข้อความ | ความหมาย |
|---------|-----------|
| `ดึงจาก API ครบ N หน้า` | กวาดครบทุกหน้าแล้ว ✅ |
| `⚠ API หยุดก่อนจบที่หน้า X (HTTP 429)` | โดน rate-limit — รอสักพักแล้วสแกนใหม่ |
| `⚠ ยังไม่เจอ API รายการรูป` | ให้เลื่อนหน้า Grok เอง 1-2 จอแล้วสแกนใหม่ |
| `เทียบสื่อจาก id (N)` | ตาข่ายกันตกขั้นสุดท้าย — เจอ 0 คือสัญญาณดี (แปลว่า API เก็บครบแล้ว) |
| `❌ ชื่อไฟล์ (HTTP 403)` ตอนโหลด | ปัญหาสิทธิ์/คุกกี้ — แจ้ง Claude |

## ความรู้ทางเทคนิคที่ได้จากการซ่อม (ใช้ซ้ำได้กับงานอื่น)

1. **"เห็นรูปแต่โหลดไม่ได้" ใน extension = ปัญหาคุกกี้แทบทุกครั้ง** — `<img>` ในหน้า extension แนบคุกกี้อัตโนมัติ แต่ `fetch()` ค่า default **ไม่แนบ** (ต้องใส่ `credentials: "include"` + มี host_permissions) ไฟล์ private เลยตอบ 401/403 เฉพาะตอนดาวน์โหลด
2. **เว็บที่ grid เป็น virtualized list ต้องเก็บข้อมูลระหว่างเลื่อน** — เก็บครั้งเดียวตอนท้ายจะเห็นแค่จอเดียว เพราะ React ถอด element ที่พ้นจอออก
3. **Replay pagination API ต้องมี retry + backoff + หน่วงระหว่างหน้า** — โดน 429 ครั้งเดียวแล้ว `break` เงียบ ๆ = ได้ข้อมูลไม่ครบโดยไม่รู้ตัว และต้อง**รายงานผลเสมอ**ว่าจบสมบูรณ์หรือถูกตัด
4. **บั๊กคลาสสิก JS:** ตัวแปรใน template string ที่ไม่มีจริง (`${dup}`) ทำ ReferenceError เงียบ ๆ → UI ว่างทั้งแผงและ abort งานกลางทาง — เจอบ่อยในโค้ดที่ refactor แล้วลบตัวแปรไม่หมด
5. ~~เครื่องนี้ไม่มี node~~ **อัปเดต 07-07: ติดตั้ง Node.js LTS v24.18.0 แล้ว (winget)** — แต่ shell ใหม่ต้อง refresh PATH ก่อน: `$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')` · ข้อจำกัดเดิมที่ยังจริง: ใช้ Obsidian เป็น node แทนไม่ได้ (Electron ปิด fuse `ELECTRON_RUN_AS_NODE`)

## ประวัติการแก้ (5 ก.ค. 2026: v6.0.0 → 6.1.1)

- **v6.1.0** — ลบ `${dup}` (บั๊กหลักที่ทำ scan พังกลางทาง+UI ค้าง), replay API มี retry/backoff + เพดาน 1,000 หน้า + รายงานผลบน status, เก็บ DOM ทุกรอบระหว่างเลื่อน, จับ headers/body ของ request ให้ครบ, กู้รูปจาก id ขยายเป็น 2,000 id + probe หลายนามสกุล
- **v6.1.1** — ดาวน์โหลดแนบคุกกี้ + retry 3 ครั้ง (แก้ "โหลดไม่ได้" ทั้งแผง), โชว์สาเหตุไฟล์ที่พลาด, ตรวจซ้ำแนบคุกกี้ด้วย
